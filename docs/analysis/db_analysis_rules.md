# DB分析の基本ルール

この文書は、`csv_db/` の CSV DB を使って統計・傾向分析をするときの共通前提を定義する。
特に、思考時間系とラグ系の分析で毎回ぶれないように、最初に掛ける除外条件を固定する。

## 対象

- 主対象テーブルは `discard_fact_YYYYMM.csv`
- 必要に応じて `hanchan_master.csv` と `kyoku_master.csv` を join する
- 思考時間分析では主に `thinking_time_ms` を使う
- `thinking_time_before_reach_ms` を分析する場合も、基本は同じ外れ値ルールを適用する
- ラグ分析では主に `lag_delay_ms` を使う

## 基本除外ルール

### 1. 思考時間の下限

- `thinking_time_ms <= 900` は除外する
- 理由:
  - この UI では、かなり速く打牌選択しても概ね `1.0 秒` 前後かかる前提で扱う
  - `900ms` 以下は、観測揺れや capture ずれ、例外的操作を含む可能性が高い

### 2. 思考時間の上限

- `thinking_time_ms >= 8000` は除外する
- 理由:
  - 長考以外に、離席、通信待ち、別作業、観測欠損復帰が混ざりやすい
  - 打牌選択そのものより、局外要因の影響が強い外れ値として扱う

### 3. 自分プレイヤーの除外

- 自分プレイヤーは分析対象から除外する
- 現時点の自分プレイヤー名リスト:
  - `パシフィック`
  - `s6u`
- 理由:
  - ツール利用者本人の打牌は、分析目的によってバイアス源になりやすい
  - 検証中の打牌、試行、意図的な操作確認が混ざる可能性がある

### 4. ラグ時間の下限

- `lag_delay_ms <= 550` はラグ分析から除外する
- 理由:
  - 準備していても、鳴きスキップを `600ms` 未満で安定して行うのは難しい前提で扱う
  - `550ms` 以下は、通信遅延、アプリ遅延、capture 観測ずれなどのシステム側要因が強い外れ値とみなす
  - raw DB の記録値は残すが、集計サンプルには入れない
  - 新しい DB 運用では、この領域は `lagged = 6` として分離する

## 推奨フィルタ

### 思考時間分析

思考時間分析では、まず次の条件を掛ける。

```text
thinking_time_ms IS NOT NULL
AND thinking_time_ms > 900
AND thinking_time_ms < 8000
AND player_name NOT IN ('パシフィック', 's6u')
```

### ラグ分析

ラグ分析では、まず次の条件を掛ける。

```text
lag_delay_ms IS NOT NULL
AND lag_delay_ms > 550
AND player_name NOT IN ('パシフィック', 's6u')
```

## 補足

- この文書のルールは「最初に必ず掛ける基本フィルタ」であり、分析テーマ別の追加除外は別でよい
- たとえば、鳴き後だけを見る、リーチ後だけを見る、門前だけを見る、などの条件はこの後段で重ねる
- 自分プレイヤー名が増えたら、この文書のリストを更新する
- 将来、対戦形式や観戦由来データで別ルールが必要なら、この文書の改訂版を切る
- `lag_delay_ms <= 550` を除外しても、DB の raw 値は消さない。分析サンプルから外すだけである
- 新しいデータでは `lagged = 6` が付くが、旧データ互換のため数値条件 `lag_delay_ms > 550` も維持する
