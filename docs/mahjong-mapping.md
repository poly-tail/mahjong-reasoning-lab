# Mahjong Mapping

このUIは、ChatGPTやnoteで書いた考察を自動推論で解釈するのではなく、ユーザーが選んだテンプレートから知識ノードへ写すための作業場です。

## Mapping Inbox

`Mapping Inbox` では考察メモを貼り付け、テンプレートを選びます。

- 手牌価値レンジ
- 押し引き（読み整理）
- 危険牌比較
- 卓上動態 / 他家介入読み
- ノードロック
- 枝刈り
- 読みの有用性
- 条件戦/順位点
- 中間状態

作成される下書きは `type`、`tags`、`probability_role`、`pruning_hints`、`lock_mode` など既存schemaの範囲に収めます。schema v5は使いません。

押し引き、危険牌比較、条件戦/順位点、安全度、卓上動態は、Phase1では読み候補カテゴリ、context tag、observation candidate、exception candidate として残します。押し引き判断エンジンや牌選択メソッドとしては扱いません。

## 手牌価値レンジ

手牌価値は1つの強弱ではなく、次の4軸に分けます。

- 進行度・聴牌率: シャンテン数、聴牌率、先制率、和了到達の近さ、副露速度、巡目に対する進行度
- 打点: 打点の高さ、打点レンジ、安い/中打点/満貫級/跳満級などの幅、高打点の尾部リスク
- 待ち・形の良さ: 良形/愚形、待ち候補、変化のしやすさ、危険牌比較、安全度評価への接続
- 点数状況・行動閾値: 点棒状況、順位点、親子、局、巡目、供託、本場、条件戦で読みを局面文脈上どれくらい重く扱うか

旧タグの `speed_axis`、`shape_axis`、`external_modifier`、`rank_ev` などは既存データ互換のaliasとして残します。ただし新規UIとテンプレートの主表示は4軸名を使います。

Influence edge が metric node に向いている場合、Hand Value Range Lens が軸ごとに集約します。`mixed` と `unknown` は確定扱いせず、hard pruneの根拠にはしません。

## 卓上動態 / 他家介入読み

旧称の脇救済率は、Phase1では「自分の次手番まで、または指定した短時間窓内に、脇の和了・放銃・鳴き・安牌供給・流局接近などで局面文脈が変わる可能性」として扱います。

これは他力期待を無制限に足す指標ではありません。必ず時間窓、イベント束、上限レンジと一緒に残します。

`q_total` は押し引きEVではありません。行動推奨へ直接接続しません。

## 中間状態

中間状態モデルは Case Workspace の判断プロセス表示に対応します。

- 洗い出し
- 重み付け
- 加算/合成
- 比較
- 選択
- 反省

caseLanes自体は変更せず、attached nodes から派生表示します。
