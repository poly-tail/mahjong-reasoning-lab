# Tenhou Hojo Helper 要件定義書 v1.5

## 1. 文書位置づけ

- 本版は `requirements_v1.4.md` を継承し、2026-04-03 時点の UI・危険度ロジック・分析文書運用の更新要件を追加する。
- `v1.4` に記載済みの要件は、本書で明示的に置き換えた項目を除き有効とする。

## 2. 改版の主眼

- 自家手牌右側に外部期待値ランキングを表示する UI を追加する。
- 筋本数ベース危険度に、愚形待ちパターン加算と牌別ランキング表示を追加する。
- DB 分析で前提にする打牌前手牌 snapshot と除外ルールを明確化する。
- 管理文書、版管理文書、ロジック文書の同期運用を明文化する。

## 3. 機能要件

- `REQ-GUI-15`: 自家手牌右側に `AI TOP3` ボタンを配置し、押下時のみ期待値表示パネルを開くこと。
- `REQ-GUI-16`: `AI TOP3` パネルは小さめの牌画像と期待値文字列で上位3件を表示し、ボタンが OFF の間は新規 POST を行わないこと。
- `REQ-GUI-17`: `AI TOP3` パネルが ON の間に手牌が変化した場合は、その手牌を使って自動再取得すること。
- `REQ-GUI-18`: 各他家プレイヤーパネルの `SUMMARY` は、従来の筋ランキングに加えて牌別ランキング上位5位までを表示すること。
- `REQ-GUI-19`: 牌別ランキングは同率の牌を同一行へ最大5牌までまとめ、右端にその共通危険度を1回だけ表示できること。
- `REQ-GUI-20`: 画面表示に使う危険度は、筋補正・愚形加算を適用した最終値と一致すること。

## 4. ロジック要件

- `REQ-LOGIC-05`: 特定牌ごとの総合危険度は、無筋危険度に対して愚形最大3パターンを加算して算出すること。
- `REQ-LOGIC-06`: 愚形加算パターンは `カンチャン` `シャンポン` `ペンチャン(3/7のみ)` とし、基本加算は各 `2%` とすること。
- `REQ-LOGIC-07`: 最終手出し前のスペース事情により愚形が薄くなる牌は、カンチャン `0.6%`、シャンポン `1%` へ減衰すること。
- `REQ-LOGIC-08`: 4見えで物理否定できる愚形パターンは `0%` とし、2見え/3見えのシャンポン減衰と、自手偏在による `+1%` 濃度補正を反映すること。
- `REQ-LOGIC-09`: 危険度ロジックが参照する可視枚数は、河・副露・ドラ表示・自手牌を含む 34 種集計であること。
- `REQ-LOGIC-10`: 他家聴牌度合いロジックの考え方は `docs/mahjong/logic/opponent_tenpai_readiness.md` に整理し、実装前段の設計基準として扱うこと。

## 5. データ要件

- `REQ-DATA-14`: 打牌行に保存する手牌情報は、打牌後ではなく打牌前の concealed hand snapshot を基準とすること。
- `REQ-DATA-15`: `discard_fact` には `discard_tile_37_text` と `seat0..3_hand_tiles_37_text` を持ち、値は `33m 22p 11s 77z` 形式の plain text とすること。
- `REQ-DATA-16`: 37 種手牌文字列は 136 ID 順に並べたうえで、同種牌を `334m` 形式にまとめ、牌種間のみ半角スペースで区切ること。
- `REQ-DATA-17`: 打牌分析用シャンテン計算と両面固定判定は、前項の打牌前 snapshot を入力として計算すること。

## 6. DB・分析要件

- `REQ-DB-09`: `hanchan_master` は XML / URL リスト入力で半荘照合できた場合、元の入力 URL を `source_url` に保存すること。
- `REQ-DB-10`: `--xml-url-list` は各 URL を独立に半荘照合し、それぞれの結果を DB へ反映すること。
- `REQ-ANL-01`: DB 分析の共通外れ値除外条件として、`thinking_time_ms <= 900` と `thinking_time_ms >= 8000` を除外すること。
- `REQ-ANL-02`: DB 分析では自分プレイヤー `パシフィック`、`s6u` を分析対象外とすること。
- `REQ-ANL-03`: 上記分析前提は `docs/analysis/db_analysis_rules.md` に集約し、他文書から参照できること。

## 7. 運用・保守要件

- `REQ-OPS-02`: 仕様変更時は `requirements/current.md`、`specs/current.md`、`screen_specs/current.md` を最新 versioned file へ張り替えること。
- `REQ-OPS-03`: 管理文書として `project_guide.md`、`source_overview.md`、`folder_structure.md`、`src_call_graph.md`、`changelog.md` を同期更新すること。
- `REQ-OPS-04`: 主要ロジック・分岐・データ定義を持つソースには、処理まとまり単位の説明コメントを入れること。

## 8. 非機能要件

- `NFR-MAINT-03`: UI 表示値とロジック計算値の不一致を避けるため、表示用集計はロジック側の最終結果を再利用すること。
- `NFR-MAINT-04`: 外部 POST 連携は request / response / 描画用 snapshot を分離して扱うこと。
- `NFR-DOC-01`: `docs/mahjong/` と `docs/analysis/` は、画面仕様や DB 設計を直接重複説明せず、ルールと分析方針の基準文書として保守すること。外部連携や transport は `docs/integrations/` に分けること。
