# Tenhou Hojo Helper 要件定義書 v1.2

## 1. 目的
- 天鳳対局で発生する捨て牌をリアルタイムに可視化し、プレイヤーの意思決定を支援するデスクトップ補助ツールの要件を定義する。

## 2. スコープ
- GUI アプリケーション本体、牌画像の読み込みと描画、捨て牌可視化ロジック、外部キャプチャモジュールとの連携インターフェースを対象とする。
- ネットワーク伝送、牌認識アルゴリズム、高度な牌譜解析は対象外とする。

## 3. 用語
- **座席 (プレイヤー)**: 自家・下家・対面・上家の 4 プレイヤー。
- **捨て牌リスト (`sutehaiLL`)**: 座席ごとの捨て牌履歴を保持するコレクション。
- **ドロー種別 (`draw_type`)**: 手出しとツモ切りを区別する値。

## 4. システム概要
- Python 3.x で実装し、`tkinter` による GUI と `Pillow` による画像処理を用いる。
- ローカルの牌画像アセット `1.png`～`37.png` を読み込んで描画する。
- `TenhouCapture` などの外部キャプチャコンポーネントが捨て牌データを GUI に供給する。

## 5. 利用者
- 天鳳の対局を振り返るプレイヤーや解析者。
- ツールの保守・機能追加を担当する開発者。

## 6. 機能要件
- **REQ-GUI-01**: タイトル「Tenhou Helper」を持つメインウィンドウで 4 プレイヤー分の捨て牌エリアを同時表示する。
- **REQ-GUI-02**: 起動時に標準牌と赤牌の画像を読み込み、座席の向きに合わせて回転表示できる。
- **REQ-GUI-03**: 手出しとツモ切りを色調やアイコンなどで判別できる視覚的手がかりを提供する。
- **REQ-GUI-04**: 座席ごとのパネルに捨て牌を描画し、利用者が座席位置を即座に認識できるようにする。
- **REQ-GUI-05**: 捨て牌を時系列順に配置し、一定枚数で折り返すレイアウトを維持する。
- **REQ-GUI-06**: 再描画後もウィンドウ操作が継続可能で、UI がフリーズしない。
- **REQ-DATA-01**: 座席単位の捨て牌データとして牌 ID とドロー種別を受け付ける。
- **REQ-DATA-02**: 局ごとの時系列を保持し、画面表示が取得順を反映する。
- **REQ-CAP-01**: `tshark` 出力からプレイヤータグ (T/U/V/W) を抽出し、座席とツモ切り状態にマッピングする。
- **REQ-CAP-02**: `frame.time_epoch` を用いてタイムスタンプと時間差を計算する。
- **REQ-DATA-03**: 各タグエントリをローカル DB に永続化する。
- **REQ-DATA-04**: 各打牌イベントを SQLite に記録し、牌 ID、ドロー種別、副露フラグ、タグ、デルタ時間、手牌スナップショットを保持する。
- **REQ-EXT-01**: 外部キャプチャモジュールから捨て牌更新を受け取り再描画できる。
- **REQ-OPS-01**: 局開始時に表示内容をリセットする。

## 7. 非機能要件
- Windows 10 以降、Python 3.x、`tkinter` を前提とする。
- 牌画像は所定のリソースパスに配置する。
- エラーはログや例外で診断できるようにする。
